# PANEL PUSH ARENA

5×5パネルを使った、複数人リアルタイム対戦ゲームです。

## ゲームルール

- 光っているパネルを押すと得点
- 押し間違いは50点減点、コンボリセット
- パネル単位のノーミスクリアで500点ボーナス
- 全プレイヤーが同じ順番の配置に挑戦
- 難易度ごとに2ラウンドごとに光る枚数が1枚増加

| 難易度 | 光る枚数 |
| --- | ---: |
| EASY | 1–3 |
| NORMAL | 3–7 |
| HARD | 5–10 |
| EXPERT | 7–15 |
| MASTER | 9–17 |
| LUNATIC | 12–22 |

待機ルームではチャットを利用できます。ゲーム開始後はチャットの取得・送信とも停止します。

## 待機中のホスト操作

- 引数なしの `/kick`：ホスト・BOTを含む全員を退出させ、ルームと待機チャットを削除します。削除したコードでは再参加できません。

## 裏難易度

ルーム作成時・ゲーム設定で通常6種類に加えて裏6種類を選べます。出現枚数の範囲は表と共通です。
ダメージへの変化確率は裏EASY 10%、裏NORMAL 20%、裏HARD 30%、裏EXPERT 35%、裏MASTER 40%。裏LUNATICは盤面ごとに10〜50%（1%刻み）の確率を抽選します。同じ盤面は全員共通です。
赤い×のダメージパネルを押すと2000点減点・コンボ解除し、クリアボーナスなしで次の盤面へリセットします。残った通常パネルを全て押せばクリアです。進行不能を防ぐため通常パネルは最低1枚残します（出現1枚の場合は通常パネルのみ）。BOTにも同じルールを適用します。追加SQLは不要です。

- `/kick 対象ユーザー名`：対象をルームから退出させます。BOTも対象にできます。ホスト自身・名前が重複する対象は指定できません。BANではないため再参加は可能です。

各プレイヤーが「準備完了」を押し、全員がオンラインかつ準備完了になるとホストが開始できます。BOTは自動で準備完了になります。開始後はサーバー共通の開始時刻で3秒カウントダウンし、その間は入力とBOTの進行を停止します。制限時間にはカウントダウンを含みません。

設定・BOT・ハンデの変更時と再戦時は準備状態を解除します。再戦はホストの「待機ルームへ」から行います。準備状態用のテーブル `panel_readiness` はAPIが自動作成するため、この更新のための手動SQLは不要です。

- `/bot 2 3`：レベル3のBOTを2人追加。人間とBOTを合わせて最大8人です。
- `/handicap 名前 1000`：指定プレイヤーの開始点を1000点に設定。負数も指定可能、0で解除します。名前に空白がある場合も使用できます。
- 「ゲーム設定」から制限時間（30・60・90秒）と6段階の難易度を変更できます。

BOTの速度と正答確率はレベル順に 2枚/秒・75%、2.5枚/秒・77%、3枚/秒・77%、3.5枚/秒・80%、4枚/秒・85% です。通常プレイヤーと同じ得点計算を使います。

既存データベースには `commands-migration.sql` を一度実行してください。新規の場合は `pages-init.sql` の後に実行します。新しいAPIの利用にはこの項目追加が必要です。

## 開発

```bash
pnpm install
node scripts/build-pages.mjs
node scripts/check-pages.mjs
```

ゲームデータには専用のCloudflare D1 `panel-push-db` を使用します。空のデータベースには `pages-init.sql` を実行してください。接続名はリポジトリ直下の `wrangler.toml` にある `PANEL_DB` です。既存ゲームの `DB` は変更しません。

## ビルド

```bash
node scripts/build-pages.mjs
```

`pages-output/` の index.html、game.js、game.css、favicon.svg をリポジトリの `public/panel-push/` に配置し、pages-function.js を `functions/api/panel-push.js` に配置します。これらの生成物はリポジトリに同梱しています。Pagesのビルドコマンドは空欄、出力先は既存どおり `public` です。

公開先: https://yume3neko.pages.dev/panel-push/

データベース初期化とPagesのデプロイ成功の両方が必要です。ローカルの処理確認はSQLiteによるもので、本番のD1接続確認は別途行います。
